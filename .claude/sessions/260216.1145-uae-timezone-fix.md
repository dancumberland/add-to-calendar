## Implementation Details

### Bug 1: Missing Timezone Mapping (Critical)
Kit is a Rails app. Its timezone picker sends Rails `ActiveSupport::TimeZone` names. For GMT+4, Rails uses "Abu Dhabi" (→ Asia/Muscat), NOT "Dubai." Our map only had `'Dubai (GMT+04:00)': 'Asia/Dubai'`, so "Abu Dhabi" fell through all matching stages to UTC fallback.

For users ahead of UTC (like Dubai, GMT+4): Kit's date picker sends midnight local time as UTC. Feb 10 midnight Dubai = Feb 9 20:00 UTC. With correct timezone mapping, UTC→Dubai conversion recovers Feb 10. With UTC fallback, date stays Feb 9. Off by one day.

For users behind UTC (like MST, GMT-7): Feb 10 midnight MST = Feb 10 07:00 UTC. Even with UTC fallback, the date is still Feb 10. Bug is invisible.

### Bug 2: Dangerous Partial Match
The old partial-match logic split timezone names on space and checked if the first word was a substring. "St" from "St Johns" matched the "st" in "Gulf Standard Time" — mapping GMT+4 to Newfoundland (GMT-3:30), a 7.5-hour error.

### Bug 3: Single-Digit Hour Parsing
Luxon's `hh:mm` format requires zero-padded hours (01-12) and rejects "2:00". Changed to `h:mm` which accepts both "2:00" and "02:00". The validation regex already accepted 1-2 digit hours, so these were out of sync.

### Fix Applied
1. Replaced 70-entry TIMEZONE_MAP with complete 134-entry Rails ActiveSupport::TimeZone mapping
2. Rewrote `mapTimezoneToIANA()` with 6-step matching: null check → IANA passthrough → exact match → case-insensitive → strip offset and rematch → extract GMT offset as fixed timezone → UTC with loud error
3. Changed Luxon format from `'yyyy-MM-dd hh:mm a'` to `'yyyy-MM-dd h:mm a'`
4. Added legacy aliases for backwards compatibility with previously-observed formats

## Key Decisions
- **Complete Rails list vs. incremental additions**: Went with the full 134-entry list to prevent future whack-a-mole. Kit is a Rails app, so this is the authoritative source.
- **GMT offset fallback**: Rather than ever silently falling to UTC, extract the numeric offset from the timezone string. For non-DST zones like Dubai, a fixed offset is identical to named timezone. For DST zones, it's at worst 1 hour off vs. potentially 12 hours with UTC.
- **Removed partial match entirely**: The substring matching was too dangerous. Replaced with exact matching after stripping offset suffixes, which is precise.
