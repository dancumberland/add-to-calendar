## Context
Users reported issues with the Add to Calendar plugin:
1. Outlook calendar showing wrong date/time (correct zoom link, wrong date)
2. iCal users getting "cannot find ICS" errors
3. Enterprise Outlook users being redirected to create personal accounts

## Objectives
1. Fix Outlook date/time format issue
2. Fix iCal download reliability
3. Add support for Office 365/enterprise users
4. Implement automated weekly testing to prevent future regressions

## Implementation Details

### Root Cause Analysis

**Issue 1: Outlook Date Format**
- Was using Google's compact format (`20250215T180000Z`)
- Outlook requires ISO 8601 with separators (`2025-02-15T18:00:00Z`)

**Issue 2: Timezone Date-Shift Bug (Critical)**
- `DateTime.fromISO(dateISO, { zone: ianaTimezone }).toISODate()` was shifting dates back one day
- Midnight UTC on Feb 15 = 4 PM on Feb 14 in Pacific, causing wrong date
- Fix: Extract date directly from ISO string: `dateISO.split('T')[0]`

**Issue 3: iCal Download Attribute**
- `download="invite.ics"` attribute conflicted with server `Content-Disposition` header
- Fix: Removed redundant download attribute

**Issue 4: Enterprise Outlook**
- Only supported `outlook.live.com` (consumer)
- Fix: Added `outlook.office.com` button for enterprise/work accounts

### Changes

1. Added `formatDateForOutlook()` for ISO 8601 format
2. Fixed timezone date parsing to preserve user's selected date
3. Added Office 365 URL generation
4. Updated HTML to show 4 buttons: Google, Apple, Outlook, Office 365
5. Created test endpoint with timezone test cases
6. Added weekly cron job in vercel.json

## Key Decisions

1. **Office 365 as separate button** - Rather than auto-detecting, provide both options since users know their account type
2. **Direct date extraction** - Using `dateISO.split('T')[0]` instead of Luxon parsing to avoid timezone interpretation
3. **Weekly testing schedule** - Mondays at 12:00 UTC to catch any drift before weekend usage
