## Quick Summary

Dan's weekly email reports were missing 7 weeks of historical data because daily usage counters expired after 30 days. Implemented Option B (weekly aggregates) to store persistent 12-week trend data that never expires, while keeping detailed daily breakdowns short-lived.

---

## Work Completed

### 1. Root Cause Analysis ✅
**Problem**: 12-week trend graph showed zeros for Sep 14 - Oct 26
- Daily data (`usage:YYYY-MM-DD`) stored with 30-day expiration
- Weekly report queries 12 weeks (84 days) of daily data
- Data older than 30 days deleted = zeros in report

**Data Architecture Found**:
- `calendar-block API`: Tracks daily usage with timezone/eventType breakdown
- `weekly-report API`: Generates emails from daily data (no persistence layer)
- `Vercel KV`: Short-lived daily keys + all-time total counter

### 2. Implemented Option B: Weekly Aggregates ✅
Created `utils/analytics.js` - centralized analytics module with:

**Functions**:
- `trackDailyUsage()`: Increments daily counters (30-day TTL) + all-time total
- `aggregateWeeklyData()`: Locks in week totals with 365-day expiration (ONE YEAR)
- `getTwelveWeekTrend()`: Queries preferred weekly aggregates, falls back to daily math
- `getAllTimeStats()`: Returns persistent all-time metrics

**Storage Strategy**:
- Daily keys: `usage:daily:YYYY-MM-DD` (30 days) - detailed breakdown preserved
- Weekly keys: `usage:weekly:YYYY-MM-DD` (365 days) - historical trend data locked
- Total counter: `usage:total` (no expiration) - all-time metrics

**How It Works**:
1. Each event creates increments daily counter + updates all-time total
2. At end of week, `aggregateWeeklyData()` sums 7 days into weekly aggregate (called by cron)
3. Weekly report pulls from aggregates (persistent) when available
4. Falls back to daily math if aggregate doesn't exist yet

## Technical Details

### Data Flow After Fix

```
Event Created (Kit Plugin)
    ↓
calendar-block API
    ↓
trackDailyUsage() in analytics.js
    ├─ Update daily: usage:daily:YYYY-MM-DD (30-day TTL)
    └─ Update total: usage:total (no expiration)

Weekly (via Cron/Manual)
    ↓
weekly-report API calls aggregateWeeklyData()
    ↓
Sums 7 days into usage:weekly:YYYY-MM-DD (365-day TTL)

Weekly Report Generation
    ↓
getTwelveWeekTrend() pulls 12 weeks
    ├─ Prefers usage:weekly:* keys (persistent)
    └─ Falls back to daily math (temporary)

Email Sent
    ↓
All 12 weeks populated (no missing data!)
```

### TTL Strategy

| Key Pattern | TTL | Purpose | Retention |
|---|---|---|---|
| `usage:daily:*` | 30 days | Event details & breakdown | Temporary |
| `usage:weekly:*` | 365 days | Week totals | Persistent (1 year) |
| `usage:total` | None | All-time count | Permanent |
